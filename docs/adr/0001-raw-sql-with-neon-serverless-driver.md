# ORM 없이 Neon 서버리스 드라이버로 SQL을 직접 쓴다

테이블이 3~4개뿐이고 쿼리가 목록 조회(필터·검색·정렬·커서), 리액션 토글, CRUD 정도로 한정되어 있어, Drizzle·Prisma 같은 ORM 대신 `@neondatabase/serverless`의 `neon()` HTTP 드라이버와 태그드 템플릿 SQL을 직접 쓴다. v1부터 템플릿 쿼리를 파라미터째 합성할 수 있어 동적 WHERE/ORDER BY도 SQL 인젝션 없이 조립할 수 있고, HTTP 드라이버라 Vercel 서버리스에서 커넥션 수 문제가 생기지 않는다.

## Consequences

- 쿼리 결과 타입은 자동 추론되지 않으므로, Kudo·Reaction을 다루는 SQL은 Kudo 모듈 한곳에만 두고 그 경계에서 행(row)을 도메인 타입으로 변환한다.
- 예외(2026-09-29 추가): Kudo 도메인이 아닌 SQL은 각자 자기 모듈에 둔다. 요청 횟수 제한(`rate_limits` 테이블)은 유스케이스가 아니라 운영 장치이므로 전용 모듈이 가지며, Kudo 모듈은 그 모듈의 함수만 호출한다. 마이그레이션·시드 스크립트는 앱 밖에서 한 번씩 실행하는 도구라 SQL을 직접 쓴다.
- 예외(2026-09-29 추가): 테스트는 API로 만들 수 없는 조건(예: 7일 전에 작성된 Kudo)을 준비할 때만 SQL로 데이터를 직접 바꿀 수 있다. 시간은 시스템 경계이기 때문이다. 검증은 항상 API 응답으로 한다.
- 스키마 변경은 `db/migrations/`의 번호 붙은 `.sql` 파일과 이를 순서대로 적용하는 작은 스크립트로 관리한다.
- `sql.unsafe()`는 화이트리스트로 검증된 식별자(정렬 컬럼 등)에만 쓴다.
