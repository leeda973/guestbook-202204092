# 도메인 문서

엔지니어링 스킬이 코드베이스를 탐색할 때 이 저장소의 도메인 문서를 어떻게 활용해야 하는지 설명합니다.

## 탐색 전에 읽을 것

- 저장소 루트의 **`CONTEXT.md`**, 또는
- 루트에 **`CONTEXT-MAP.md`**가 있으면 그 파일: 컨텍스트별 `CONTEXT.md`를 가리킵니다. 주제와 관련된 것을 모두 읽으세요.
- **`docs/adr/`**: 작업하려는 영역에 해당하는 ADR을 읽으세요. 멀티 컨텍스트 저장소라면 컨텍스트 범위의 결정이 담긴 `src/<context>/docs/adr/`도 확인하세요.

이 파일들이 없으면 **조용히 넘어가세요**. 없다는 사실을 지적하거나 미리 만들자고 제안하지 마세요. `/domain-modeling` 스킬(`/grill-with-docs`와 `/improve-codebase-architecture`를 통해 호출됨)이 용어나 결정이 실제로 확정될 때 필요에 따라 만듭니다.

## 파일 구조

단일 컨텍스트 저장소(대부분의 저장소):

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-event-sourced-orders.md
│   └── 0002-postgres-for-write-model.md
└── src/
```

멀티 컨텍스트 저장소(루트에 `CONTEXT-MAP.md`가 있는 경우):

```
/
├── CONTEXT-MAP.md
├── docs/adr/                          ← 시스템 전체 결정
└── src/
    ├── ordering/
    │   ├── CONTEXT.md
    │   └── docs/adr/                  ← 컨텍스트별 결정
    └── billing/
        ├── CONTEXT.md
        └── docs/adr/
```

## 용어집의 어휘를 쓰세요

결과물(이슈 제목, 리팩터링 제안, 가설, 테스트 이름 등)에서 도메인 개념을 부를 때는 `CONTEXT.md`에 정의된 용어를 쓰세요. 용어집이 명시적으로 피하라고 한 동의어로 바꿔 쓰지 마세요.

필요한 개념이 아직 용어집에 없다면 신호입니다. 프로젝트가 쓰지 않는 말을 새로 만들고 있거나(다시 생각해 보세요), 실제로 빠진 용어가 있는 것입니다(`/domain-modeling`을 위해 기록해 두세요).
