# 07: 인기순 정렬

**What to build:** Visitor가 최신순·인기순 탭을 전환한다. 인기순에서는 리액션 합계가 많은 Kudo가 먼저 나오고, 합계가 같으면 항상 같은 순서로 보인다. 스크롤해도 카드가 겹치지 않으며, 정렬 상태도 주소창에 반영된다.

**Blocked by:** 05 (카테고리 필터와 검색), 06 (Reaction 토글)

**Status:** resolved

- [ ] GET 목록이 `sort=popular`일 때 (리액션 총합 desc, id desc)로 정렬한다
- [ ] 인기순 커서는 다음 페이지의 시작 위치(offset) 정수다. 해석할 수 없으면 400이다
- [ ] 인기순도 category·q 필터와 함께 동작한다
- [ ] 클라이언트는 페이지를 이어 붙일 때 id 기준으로 중복을 제거한다
- [ ] 최신순·인기순 탭이 있고, 선택한 정렬이 주소창에 반영되며 첫 렌더에도 적용된다
- [ ] Route Handler 테스트가 정렬 순서, 동점 처리, 페이지 이어 받기를 검증한다
- [ ] 수동 확인: 인기순에서 Reaction을 누른 뒤 스크롤해도 카드가 두 번 보이지 않는다

## Comments

- 2026-09-28: 구현 완료. 테스트 5개 통과(합계 순·동점은 최신 먼저, offset 커서로 25개 중복·누락 없음, 카테고리와 조합, 알 수 없는 정렬 400, 기본은 최신순). 최신순·인기순 탭을 추가했고, 인기순은 주소에 `sort=popular`로만 남긴다(최신순은 기본값이라 생략). 클라이언트는 id로 중복을 걸러낸다. 실행 중인 앱에서 `/?sort=popular`로 들어오면 인기순 탭이 선택된 채로 그려지는 것을 확인했다.
  - 참고: 이 티켓은 테스트와 구현을 한 단계에서 함께 작성해, 테스트가 먼저 실패하는 것을 따로 확인하지 않았다.
  - 남은 수동 확인: 인기순에서 Reaction을 누른 뒤 스크롤해도 카드가 두 번 보이지 않는지.
