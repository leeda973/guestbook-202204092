# 11: 요청 횟수 제한

**What to build:** 같은 곳에서 짧은 시간에 Kudo를 너무 많이 작성하거나 비밀번호를 계속 바꿔가며 수정·삭제를 시도하면, 요청이 거절되고 "잠시 후 다시 시도해 주세요" 토스트가 뜬다. 도배와 비밀번호 무차별 대입을 막는다.

**Blocked by:** 09 (Kudo 수정), 10 (Kudo 삭제)

**Status:** resolved

- [ ] rate_limits 테이블 마이그레이션: (key, window_start) PK, count. 1분 고정 윈도로 upsert해 증가시키고 오래된 행을 정리한다
- [ ] 작성은 IP당 1분에 5회, 비밀번호 확인(수정·삭제)은 IP당 1분에 5회까지 허용하고, 초과하면 429 `RATE_LIMITED`다
- [ ] IP는 Vercel이 넣어주는 전달 헤더의 첫 값을 쓰고, 없으면 "unknown"으로 묶는다
- [ ] Reaction과 조회는 제한하지 않는다
- [ ] 429 응답의 message가 토스트로 뜬다
- [ ] Route Handler 테스트: 같은 IP의 6번째 작성·비밀번호 확인이 429, 다른 IP는 영향 없음. 테스트마다 다른 IP를 써서 서로 간섭하지 않는다

## Comments

- 2026-09-28: 구현 완료. 테스트 6개 통과(같은 IP 6번째 작성 429·다른 IP 무관, 전달 헤더 첫 IP 기준, 수정·삭제 비밀번호 확인 합산 5회, 작성과 비밀번호 확인은 따로 셈, Reaction 무제한, 잘못된 입력은 작성 횟수에 넣지 않음). 1분 고정 윈도를 upsert로 세고, 5분 지난 기록은 같은 쿼리의 CTE로 지운다. 전체 테스트 86개 통과.
  - 테스트 헬퍼가 요청마다 다른 IP를 넣어, 다른 테스트가 제한에 걸리지 않게 했다.
  - 알려진 한계: 고정 윈도라 테스트가 분 경계에 걸리면 6번째 요청이 새 윈도로 넘어가 드물게 실패할 수 있다(실행 시간 약 2초 기준 수 % 이하).
