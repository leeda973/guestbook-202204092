# 03: Kudo 작성하고 최신순 목록에서 보기

**What to build:** 첫 트레이서 불릿. Visitor가 화면 우하단의 작성 버튼을 눌러 Kudo를 남기면, 목록 맨 위에 쿠도 카드로 나타난다. 모바일에서는 바텀 시트, 데스크톱에서는 모달로 작성 창이 열린다. 첫 화면은 서버에서 최신 Kudo 20개를 그려서 보여주고, Board가 비어 있으면 첫 Kudo를 유도하는 안내가 나온다.

**Blocked by:** 02 (개발 기반: 테스트·마이그레이션·앱 뼈대)

**Status:** resolved

- [ ] kudos 테이블 마이그레이션이 스펙의 컬럼·check 제약을 따른다
- [ ] POST 작성: 정상 요청은 201과 KudoView를 돌려준다. 응답 어디에도 비밀번호 관련 필드가 없다
- [ ] POST 작성: trim 후 빈 Author는 "익명", 빈 Recipient는 null로 저장된다
- [ ] POST 작성: Message 누락·공백만·200자 초과, Author·Recipient 20자 초과, 비밀번호 4자 미만·20자 초과는 400 `VALIDATION_FAILED`와 fieldErrors를 돌려준다
- [ ] 비밀번호는 Node 내장 crypto의 scrypt로 salt와 함께 해시해 저장한다
- [ ] GET 목록: id desc 순으로 최대 20개를 돌려준다(커서는 04번 티켓)
- [ ] 검증은 클라이언트 폼과 서버가 같은 Zod 스키마를 쓴다
- [ ] 첫 화면은 Server Component가 Kudo 모듈을 직접 호출해 렌더링하고, 그 결과가 TanStack Query 초기 데이터가 된다
- [ ] 쿠도 카드에 Author, Recipient(있을 때만), Category 색·라벨, Message, 상대 시간(마우스를 올리면 절대 시각)이 보인다
- [ ] 카드는 모바일 1열, 태블릿 2열, 데스크톱 3열 메이슨리로 배치된다
- [ ] 작성 폼: Category 필수 선택, Message 실시간 "N/200" 카운터와 200자 입력 제한, 비밀번호 분실 안내 문구, 제출 중 버튼 비활성화, 필드 아래 한국어 오류 문구
- [ ] 작성 성공 시 창이 닫히고 성공 토스트와 함께 새 카드가 목록 맨 위에 나타난다
- [ ] Board가 비었을 때 "첫 번째 응원 메시지를 남겨보세요! 🎉" 안내와 작성 버튼이 보인다
- [ ] 로딩 중 스켈레톤, 불러오기 실패 시 "다시 시도" 버튼이 있다
- [ ] Route Handler 테스트가 위 API 동작을 검증한다
- [ ] 수동 확인: 모바일 폭에서 바텀 시트, 데스크톱 폭에서 모달로 작성 창이 열린다

## Comments

- 2026-09-28: 구현 완료. Route Handler 테스트 16개 통과(작성 정상·trim·기본값·비밀번호 비노출·보이는 글자 수 기준 200자·필드별 400·JSON 아닌 본문 400, 목록 최신순·20개 제한·빈 목록). 실제 앱에서 빈 Board 안내 → 작성 → 카드 표시를 확인했다.
  - 스펙과 다른 점: `id`를 bigint 대신 integer identity로 했다(API에서 숫자로 다루기 위해). DB의 message check는 코드 포인트 기준 1~1000자 안전망이고, 200자 제한은 앱이 보이는 글자(grapheme) 기준으로 검증한다.
  - 남은 수동 확인: 모바일 폭 바텀 시트 / 데스크톱 폭 모달 전환은 브라우저에서 직접 확인이 필요하다(`npm run dev` 후 창 폭 조절).
