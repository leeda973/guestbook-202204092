# 09: Kudo 수정

**What to build:** Author가 쿠도 카드 메뉴에서 "수정"을 고르면 작성할 때와 같은 폼이 수정 모드로 열린다. 비밀번호를 함께 입력해 Message, Category, Recipient를 고치면 카드가 바로 갱신되고 "(수정됨)" 표시가 붙는다. 비밀번호가 틀리거나 이미 삭제된 Kudo면 토스트로 알려준다.

**Blocked by:** 03 (Kudo 작성하고 최신순 목록에서 보기)

**Status:** resolved

- [ ] PATCH 수정: 올바른 비밀번호면 200과 갱신된 KudoView를 돌려주고 `editedAt`이 채워진다
- [ ] Author와 비밀번호는 바뀌지 않는다
- [ ] 틀린 비밀번호는 403 `INVALID_PASSWORD`("비밀번호가 일치하지 않습니다"), 없는 id는 404 `NOT_FOUND`("이미 삭제된 Kudo예요")다
- [ ] 수정 입력도 작성과 같은 검증 규칙을 따르며 위반 시 400이다
- [ ] 비밀번호 비교는 상수 시간 비교를 쓴다
- [ ] 카드 메뉴(⋯)에 수정 항목이 있고, 작성 폼 컴포넌트를 수정 모드로 재사용한다(기존 값이 채워진 상태)
- [ ] 수정 성공 시 캐시의 해당 카드가 응답으로 교체되고, 현재 Category 필터에 맞지 않게 되면 목록을 다시 불러온다
- [ ] 수정된 카드에 "(수정됨)" 표시가 보인다
- [ ] Route Handler 테스트가 200·400·403·404를 검증한다
- [ ] 수동 확인: 틀린 비밀번호 토스트, 수정 후 "(수정됨)" 표시

## Comments

- 2026-09-28: 구현 완료(10번과 한 커밋). 테스트 6개 통과(200과 editedAt, Author·비밀번호 불변, 받는 사람 비우기, 틀린 비밀번호 403·내용 불변, 없는 id 404, 수정 검증 400). 카드 메뉴(⋯)에서 작성 폼을 수정 모드로 재사용하며(Author 입력 비활성화), 성공하면 캐시의 카드를 교체한 뒤 목록을 다시 불러와 필터 불일치도 맞춘다. 비밀번호 비교는 `timingSafeEqual`이다. 실행 중인 앱에서 틀린 비밀번호 403, 수정 후 "(수정됨)" 표시를 확인했다.
  - 남은 수동 확인: 브라우저에서 틀린 비밀번호 토스트와 수정 모드 폼.
