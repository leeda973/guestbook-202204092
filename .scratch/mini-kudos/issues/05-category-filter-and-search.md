# 05: 카테고리 필터와 검색

**What to build:** Visitor가 전체·응원·피드백·감사·칭찬 중 하나를 골라 Kudo를 걸러보고, 키워드로 Message·Author·Recipient를 한꺼번에 검색한다. 필터와 검색어는 주소창에 반영되어, 새로고침하거나 링크를 공유해도 같은 화면이 나온다. 결과가 없으면 필터를 초기화할 수 있는 안내가 나온다.

**Blocked by:** 04 (무한 스크롤)

**Status:** resolved

- [ ] GET 목록이 `category`로 걸러진다. 알 수 없는 category는 400이다
- [ ] GET 목록이 `q`로 Message·Author·Recipient를 대소문자 무시 부분 일치로 검색한다. trim 후 빈 검색어는 무시한다
- [ ] 검색어의 `%`, `_`, `\`는 글자 그대로 찾는다(테스트로 검증)
- [ ] 필터·검색과 커서 페이지네이션이 함께 동작한다
- [ ] 필터 칩과 검색 입력이 있고, 검색은 300ms 디바운스된다
- [ ] 필터·검색 상태가 주소창 쿼리 문자열에 반영되며 히스토리를 쌓지 않는다. 그 주소로 직접 들어오면 첫 렌더부터 같은 결과가 나온다
- [ ] 조건에 맞는 결과가 없으면 "조건에 맞는 Kudo가 없어요" 안내와 "필터 초기화" 버튼이 보인다. Board 자체가 빈 경우의 안내와 구분된다
- [ ] 수동 확인: 필터·검색 후 새로고침, 주소 복사 후 새 탭에서 열기

## Comments

- 2026-09-28: 구현 완료. 테스트 6개 통과(카테고리 필터, 알 수 없는 카테고리 400, 메시지·작성자·받는 사람 대소문자 무시 검색, `%`·`_`·`\` 글자 그대로 검색, 공백 검색어 무시, 필터+검색+커서 조합). 주소창은 `history.replaceState`로 바꿔 서버 왕복 없이 갱신하고, 직접 들어온 주소는 서버가 같은 필터로 첫 페이지를 그린다(실행 중인 앱에서 확인).
