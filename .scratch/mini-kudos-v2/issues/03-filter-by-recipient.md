# 03: 받는 사람별 모아보기

**What to build:** Visitor가 쿠도 카드의 "To. 지영"을 누르면 지영이 받은 Kudo만 모아 본다. 필터 영역에 "To. 지영 ✕" 칩이 생기고 주소에 `?to=지영`이 남아, 새로고침하거나 주소를 공유해도 같은 화면이 나온다. 앞뒤 공백과 대소문자만 다른 이름은 같은 Recipient로 모이고, "김지영"처럼 다른 이름은 섞이지 않는다. 카테고리·검색·정렬과 함께 쓸 수 있다.

**Blocked by:** None (can start immediately)

**Status:** resolved

- [ ] GET 목록에 `to` 조건이 있다. 앞뒤 공백을 자르고 대소문자를 무시한 정확히 일치이며, 빈 값은 무시하고 보이는 글자 20자 초과는 400이다
- [ ] `to`가 category·q·sort·cursor와 함께 동작한다
- [ ] Route Handler 테스트: 정확히 일치만(부분 일치 제외), 공백·대소문자 무시, 받는 사람 없는 Kudo 제외, 조건 조합과 커서, 20자 초과 400
- [ ] 목록 필터의 주소창 파싱·직렬화에 `to`가 추가되고, 서버 첫 렌더도 `to`를 반영한다
- [ ] 카드의 "To. 이름"이 `to` 조건을 설정하는 버튼이다(접근 가능한 이름 포함)
- [ ] 필터 영역에 "To. 이름 ✕" 칩이 보이고, ✕는 `to`만 해제한다
- [ ] `to` 조건으로 결과가 없으면 기존 "조건에 맞는 Kudo가 없어요"와 필터 초기화가 보인다
- [ ] 수동 확인: 카드의 받는 사람 클릭, 칩 해제, 새로고침 후 유지

## Comments

- 2026-09-29: 구현 완료. 테스트 5개 통과(정확히 일치만·부분 일치 제외, 공백·대소문자 무시, 카테고리·검색·인기순 조합, 커서, 빈 값 무시·20자 초과 400). 전체 테스트 98개 통과. 실행 중인 앱에서 `/?to=서연`이 서연의 Kudo 2개와 "To. 서연 ✕" 칩으로 그려지는 것을 확인했다.
  - 카드의 "To. 이름"은 버튼 대신 `/?to=이름` 링크로 만들었다. 보드와 Kudo Page(04번)에서 같은 동작이 되고, 뒤로 가기로 이전 목록에 돌아갈 수 있다. 대신 누르면 다른 필터는 풀리고 그 사람의 전체 Kudo가 보이며, 칩이 생긴 뒤 카테고리·검색·정렬을 더할 수 있다.
  - 남은 수동 확인: 브라우저에서 카드 클릭 → 칩 해제 → 새로고침.
