# 04: Kudo Page와 공유 버튼

**What to build:** Author가 쿠도 카드의 공유 버튼을 누르면 모바일에서는 시스템 공유 창이 열리고, 지원하지 않는 환경에서는 Kudo Page 주소가 복사되며 "링크를 복사했어요" 토스트가 뜬다. 공유받은 사람이 `/k/123`을 열면 그 Kudo 한 장이 크게 보이고, 리액션을 누르거나(작성자라면) 수정·삭제하거나 "보드 전체 보기"로 이동할 수 있다. 탭 제목은 "지영님에게 온 감사 Kudo · Mini Kudos" 형식이다. 삭제된 Kudo 주소는 "이미 삭제되었거나 없는 Kudo예요" 404 화면을 보여준다.

**Blocked by:** 01 (오류·404 화면), 03 (받는 사람별 모아보기)

**Status:** resolved

- [ ] Kudo 모듈에 단건 조회가 있고, GET `/api/kudos/{id}`가 KudoView(Visitor 기준 reacted)를 돌려준다. 없는 id·잘못된 id는 404 `NOT_FOUND`다
- [ ] Route Handler 테스트: 200과 KudoView, Visitor 기준 reacted, 없는 id·잘못된 id 404
- [ ] `/k/{id}` 페이지가 서버에서 Kudo를 그리고, 없으면 01의 404 화면을 삭제 문구로 보여준다
- [ ] Kudo Page에서 리액션·수정이 동작하고 목록 캐시와 함께 갱신된다. 삭제에 성공하면 보드로 이동한다
- [ ] Kudo Page의 "To. 이름"은 보드의 `?to=이름`으로 가는 링크다
- [ ] 탭·미리보기 제목: 받는 사람이 있으면 "{이름}님에게 온 {카테고리} Kudo · Mini Kudos", 없으면 "모두에게 남긴 {카테고리} Kudo · Mini Kudos". 설명은 메시지 앞 80자(보이는 글자 기준)
- [ ] 루트에 절대 주소 기준(`metadataBase`)이 있다: Vercel 운영 도메인 → 배포 주소 → 로컬 순
- [ ] 쿠도 카드에 공유 버튼이 있다. Web Share API가 있으면 공유 창, 취소(AbortError)는 조용히 넘어가고, 없으면 클립보드 복사와 토스트, 복사 실패 시 실패 토스트
- [ ] 수동 확인: 데스크톱에서 링크 복사, 복사한 주소로 Kudo Page 열기, 삭제된 Kudo 주소의 404, 탭 제목

## Comments

- 2026-09-29: 구현 완료. 단건 조회 테스트 3개 통과(목록과 같은 KudoView, Visitor 기준 reacted, 없는·잘못된 id 404). 전체 101개 통과.
  - Kudo Page는 서버에서 `getKudo`로 그린 뒤 단건 쿼리(`kudo`, id)로 이어받는다. 캐시 도우미가 목록과 단건을 함께 갱신해 리액션·수정이 두 곳에 반영되고, 삭제하면 보드로 이동한다. 메타데이터와 페이지는 React `cache`로 한 번만 조회한다.
  - 실행 중인 앱에서 탭 제목 "지영님에게 온 감사 Kudo · Mini Kudos", 설명(메시지), 공유 버튼, "보드 전체 보기"를 확인했다.
  - 없는 Kudo가 처음에는 HTTP 200으로 응답했다. 루트의 `loading.tsx`가 모든 페이지를 스트리밍으로 만들어서였다(Next 문서: 스트리밍 응답은 not-found여도 200). 보드 페이지와 로딩 화면을 라우트 그룹으로 옮겨 로딩 화면이 보드에만 적용되게 했고, 이제 없는·잘못된 id가 404다(봇 User-Agent 포함).
  - 남은 수동 확인: 공유 버튼은 시스템 공유 창을 여는 동작이라 자동으로 누르지 않았다. 07번 티켓에서 확인한다.
