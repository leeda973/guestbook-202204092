# 04: 비밀번호 불일치 안내 강화와 요청 한도 조정

**What to build:** Author가 수정·삭제에서 비밀번호를 틀리면 토스트와 함께 비밀번호 칸 바로 아래에 "비밀번호가 일치하지 않습니다"가 남고, 다시 입력하기 시작하면 사라진다. 삭제 창은 열린 채로 남는다. 채점자가 틀린 비밀번호를 여러 번 시험해도 매번 같은 안내를 보고, 그 뒤 올바른 비밀번호로 바로 수정·삭제할 수 있다. 같은 네트워크의 여러 채점자가 시험해도 요청 한도에 걸리지 않으며, 비정상적인 도배(IP당 1분 30회 초과)는 여전히 막힌다.

**Blocked by:** None (can start immediately)

**Status:** resolved

- [ ] 수정 폼: 403 `INVALID_PASSWORD`이면 토스트와 함께 비밀번호 칸 아래에 서버 message를 표시하고, 비밀번호를 다시 입력하면 지운다
- [ ] 삭제 창: 403이면 토스트와 함께 비밀번호 칸 아래에 같은 문구를 표시하고 창을 열어 둔다
- [ ] 요청 한도: 작성과 비밀번호 확인(수정·삭제 합산) 모두 IP당 1분 30회
- [ ] Route Handler 테스트: 같은 IP의 30번째까지 통과, 31번째 429(작성·비밀번호 확인 각각), 다른 IP 무관, 분 경계 대기 유지
- [ ] 회귀 테스트: 틀린 비밀번호로 수정 6번·삭제 6번이 매번 403 `INVALID_PASSWORD`이고, 그 뒤 올바른 비밀번호로 수정·삭제가 성공한다
- [ ] 서버의 비밀번호 검증 동작(403, 내용 불변)은 바뀌지 않는다
- [ ] 수동 확인: 수정·삭제에서 틀린 비밀번호를 넣었을 때 칸 아래 안내와 토스트

## Comments

- 2026-09-30: 구현 완료. 테스트를 먼저 30회 기준으로 바꿔 실패(3개)를 확인한 뒤 한도를 30으로 올렸다. 요청 횟수 제한 테스트 7개 통과:
  - 30번째까지 통과, 31번째 429(작성·비밀번호 확인 각각)
  - 첫 번째 IP 기준, 제한을 넘으면 올바른 비밀번호도 막힘, 다른 IP는 무관, 작성·비밀번호 확인 따로 셈, Reaction 무제한, 잘못된 입력은 세지 않음
  - **회귀:** 틀린 비밀번호로 수정 6번·삭제 6번이 매번 403 "비밀번호가 일치하지 않습니다"이고, 그 뒤 올바른 비밀번호로 수정·삭제가 성공한다(예전 한도 5회였다면 실패하던 시나리오)
  - 요청이 30회로 늘어 테스트마다 수십 초가 걸리므로, 분 경계 대기 기준을 40초로 늘리고 테스트별 제한 시간을 90초로 두었다.
- 수정 폼과 삭제 창에서 403 `INVALID_PASSWORD`이면 토스트와 함께 비밀번호 칸 아래에도 서버 문구를 남긴다. 다시 입력하면 지워지는 기존 규칙을 그대로 쓴다. 화면 확인은 05번 티켓에서 한다.
