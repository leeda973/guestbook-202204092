# Mini Kudos 제출 조건 맞춤 스펙 (v3)

Status: ready-for-agent

> 과제 공지의 요구사항·제출 방법·채점 기준에 맞춰 감점 요인을 없애는 마무리 스펙이다. 기본 스펙(`.scratch/mini-kudos/spec.md`)과 v2 스펙(`.scratch/mini-kudos-v2/spec.md`)의 결정은 여기서 바꾸는 항목을 빼고 그대로 유효하다. 용어는 `CONTEXT.md`를 따른다.

## 문제 정의 (Problem Statement)

과제는 "이름, 메시지, 작성 시각이 함께 쌓이는 미니 방명록"을 요구하고, 채점자는 배포된 화면에서 작성·조회·수정·삭제와 비밀번호 검증(수정·삭제 모두)이 요구사항대로 동작하는지 확인한다. 현재 앱에는 다음과 같은 감점 위험이 있다.

- 화면에 개발자 이름과 학번이 없다. 요구사항에 명시되어 있다.
- 이름이 선택 입력이라 비워 두면 "익명"으로 저장된다. 요구사항은 "이름, 메시지, 비밀번호를 입력해 새 글을 남길 수 있다"이다.
- 작성 시각이 "3분 전"처럼 상대 시간으로만 보인다. 정확한 시각은 마우스를 올려야 보이고, 서버(UTC)와 브라우저의 시간대가 달라 한국 시간보다 9시간 이른 값이 남을 수 있다.
- 요청 횟수 제한이 IP당 1분 5회라 문제가 생길 수 있다. 채점자가 틀린 비밀번호를 여러 번 시험하면 6번째부터 "비밀번호가 일치하지 않습니다" 대신 "잠시 후 다시 시도해 주세요"가 떠서, 비밀번호 검증이 이상하게 보인다. 같은 학교 네트워크의 여러 채점자가 한도를 나눠 쓰게 되기도 한다.
- 비밀번호 불일치 안내가 몇 초 뒤 사라지는 토스트로만 나와, 채점자가 놓칠 수 있다.
- 앱 이름이 제출 규칙(`guestbook-<학번>`)과 다르다.

## 해결 방안 (Solution)

모든 페이지의 헤더에 "만든 사람 · 이다은 (202204092)"를 항상 보이게 한다. 작성 폼의 이름을 필수 입력으로 바꾸고 입력칸 이름을 "이름"으로 한다. 작성 시각은 "3분 전 · 9월 30일 14:05"처럼 상대 시간과 한국 시간 기준의 정확한 시각을 함께 보여준다. 요청 횟수 한도를 IP당 1분 30회로 올려 채점 중에 걸리지 않게 한다. 수정·삭제에서 비밀번호가 틀리면 토스트와 함께 비밀번호 입력칸 바로 아래에도 "비밀번호가 일치하지 않습니다"를 남긴다. 앱 이름을 `guestbook-202204092`로 맞추고, 사람이 해야 하는 제출 준비(저장소·Neon·Vercel 이름, public 설정, 운영 DB 준비)를 점검표로 정리한다.

## 사용자 스토리 (User Stories)

### 개발자 정보

1. 채점자로서, 어느 페이지에서든 헤더에서 개발자 이름과 학번을 바로 보고 싶다, 그래야 누구의 과제인지 확인할 수 있다.
2. 채점자로서, 보드를 아무리 스크롤해도 개발자 정보가 보이길 원한다, 그래야 무한 스크롤 끝까지 내려가지 않아도 된다.
3. 채점자로서, Kudo Page·404 화면·오류 화면에서도 개발자 정보를 보고 싶다, 그래야 어떤 주소로 들어와도 확인할 수 있다.
4. 모바일 채점자로서, 좁은 화면에서도 개발자 정보가 잘리지 않고 보이길 원한다, 그래야 휴대폰으로 확인해도 된다.

### 작성 (이름 필수)

5. Author로서, 작성 폼에서 "이름" 입력칸을 보고 싶다, 그래야 무엇을 적어야 하는지 바로 안다.
6. Author로서, 이름을 비우고 제출하면 "이름을 입력해 주세요" 안내를 이름 칸 아래에서 보고 싶다, 그래야 무엇이 빠졌는지 안다.
7. Author로서, 공백만 입력한 이름도 빈 이름으로 거부되길 원한다, 그래야 이름 없는 글이 남지 않는다.
8. Author로서, 이름·메시지·비밀번호를 모두 넣으면 새 글이 목록 맨 위에 나타나길 원한다, 그래야 잘 남겨졌음을 안다.
9. Visitor로서, 이름이 선택 입력이던 때 "익명"으로 남은 글도 그대로 보고 싶다, 그래야 예전 글이 사라지지 않는다.
10. Author로서, 예전에 "익명"으로 남긴 글도 비밀번호로 수정·삭제할 수 있길 원한다, 그래야 이름 규칙이 바뀌어도 내 글을 관리할 수 있다.

### 작성 시각

11. Visitor로서, 각 글에서 "3분 전" 같은 상대 시간과 "9월 30일 14:05" 같은 정확한 작성 시각을 함께 보고 싶다, 그래야 마우스를 올리지 않아도 언제 쓴 글인지 안다.
12. Visitor로서, 정확한 시각이 한국 시간으로 보이길 원한다, 그래야 서버가 어디에 있든 헷갈리지 않는다.
13. Visitor로서, 올해가 아닌 글에는 연도도 함께 보이길 원한다, 그래야 오래된 글을 구분할 수 있다.
14. Visitor로서, 새로고침해도 작성 시각 표기가 서버와 화면에서 같게 유지되길 원한다, 그래야 시각이 바뀌어 보이지 않는다.
15. 모바일 Visitor로서, 좁은 카드에서도 작성 시각이 자연스럽게 줄바꿈되길 원한다, 그래야 카드 머리글이 깨지지 않는다.

### 수정·삭제의 비밀번호 안내

16. Author로서, 수정할 때 비밀번호가 틀리면 토스트와 함께 비밀번호 칸 아래에 "비밀번호가 일치하지 않습니다"가 남길 원한다, 그래야 토스트가 사라진 뒤에도 거부된 이유를 안다.
17. Author로서, 삭제할 때 비밀번호가 틀리면 삭제 창이 열린 채로 비밀번호 칸 아래에 같은 안내가 남길 원한다, 그래야 바로 다시 입력할 수 있다.
18. Author로서, 비밀번호를 고쳐 입력하기 시작하면 이전 안내가 사라지길 원한다, 그래야 새로 시도하는 중임을 안다.
19. Author로서, 비밀번호가 틀린 수정은 글 내용이 바뀌지 않길 원한다, 그래야 다른 사람이 내 글을 바꿀 수 없다.
20. Author로서, 비밀번호가 틀린 삭제는 글이 그대로 남길 원한다, 그래야 다른 사람이 내 글을 지울 수 없다.
21. 채점자로서, 틀린 비밀번호로 수정·삭제를 여러 번 시험해도 매번 "비밀번호가 일치하지 않습니다"를 보고 싶다, 그래야 비밀번호 검증이 일관되게 동작함을 확인할 수 있다.
22. 채점자로서, 틀린 비밀번호를 몇 번 시험한 뒤에도 올바른 비밀번호로 바로 수정·삭제할 수 있길 원한다, 그래야 정상 경로도 확인할 수 있다.

### 요청 횟수 제한

23. 채점자로서, 짧은 시간에 여러 글을 작성해도 막히지 않길 원한다, 그래야 여러 경우를 시험해 볼 수 있다.
24. 같은 네트워크를 쓰는 여러 채점자로서, 서로의 시험 때문에 막히지 않길 원한다, 그래야 동시에 채점할 수 있다.
25. 운영자로서, 비정상적으로 많은 요청(IP당 1분 30회 초과)은 여전히 막히길 원한다, 그래야 도배와 비밀번호 무차별 대입을 막을 수 있다.

### 제출 준비

26. 채점자로서, GitHub 저장소·Vercel 프로젝트·Neon 프로젝트 이름이 모두 `guestbook-202204092`이길 원한다, 그래야 제출 규칙을 지켰는지 바로 확인할 수 있다.
27. 채점자로서, GitHub 저장소를 로그인 없이 열어 볼 수 있길 원한다(public), 그래야 코드와 개발 과정을 확인할 수 있다.
28. 채점자로서, 배포 URL에 처음 접속했을 때 오류 없이 목록이 보이길 원한다, 그래야 게이트 조건을 통과했다고 판단할 수 있다.
29. 채점자로서, README에서 배포 URL, 개발자 정보, 기능과 개발 과정을 볼 수 있길 원한다, 그래야 무엇을 어떻게 만들었는지 한눈에 안다.

## 구현 결정 (Implementation Decisions)

### 개발자 정보

- 이름과 학번은 사이트 상수 모듈에 한 번만 정의한다(`DEVELOPER_NAME` = "이다은", `STUDENT_ID` = "202204092"). 헤더·README·메타데이터가 같은 값을 쓴다.
- 헤더의 서비스명·슬로건 아래에 "만든 사람 · 이다은 (202204092)"를 작은 글씨로 항상 표시한다. 헤더는 루트 레이아웃에 있으므로 보드·Kudo Page·404·오류 화면 모두에 나온다. 모바일에서 슬로건은 잘릴 수 있지만 개발자 정보 줄은 잘리지 않게 한다(줄바꿈 허용).

### 이름 필수 (Author)

- 작성 검증에서 이름은 **필수**다. 앞뒤 공백을 자른 뒤 비어 있으면 400 `VALIDATION_FAILED`이고, `fieldErrors.author`는 "이름을 입력해 주세요"다. 보이는 글자 20자 제한은 그대로다.
- 서버의 "익명" 기본값 처리를 없앤다. DB의 `author` 컬럼 기본값과 제약은 바꾸지 않는다. 기존 "익명" 행은 그대로 두며 마이그레이션도 없다.
- 작성 폼의 입력칸 라벨을 "이름"으로 바꾸고, placeholder "익명"을 "예: 다은"으로 바꾼다. 수정 폼은 지금처럼 이름을 바꿀 수 없다(비활성화, 기존 값 표시).
- 시드 데이터에서 작성자가 "익명"인 예시는 실제 이름으로 바꾼다. 새 규칙에서는 "익명"이라는 이름을 새로 만들 수 없는 것처럼 보이지 않게 하기 위해서다.
- 기본 스펙의 "Author가 trim 후 비면 '익명'" 결정과 사용자 스토리 24를 이 스펙이 대체한다.

### 작성 시각 표시

- 쿠도 카드의 시각 영역에 "{상대 시간} · {정확한 시각}"을 표시한다. 예: "3분 전 · 9월 30일 14:05".
- 정확한 시각은 **Asia/Seoul 시간대로 고정**해 포맷한다. 서버 렌더와 브라우저가 같은 문자열을 만들어 하이드레이션 차이가 없다. 형식은 한국 시간 기준으로 올해면 "M월 D일 HH:mm", 올해가 아니면 "YYYY년 M월 D일 HH:mm"(24시간제)이다.
- 포맷은 순수 함수(작성 시각, 기준 시각 → 문자열)로 만들어 테스트한다. 마우스를 올렸을 때 보이는 title에는 연도·요일을 포함한 전체 시각을 둔다.
- 상대 시간은 서버와 브라우저의 렌더 시점 차이로 달라질 수 있으므로, 상대 시간 부분만 하이드레이션 경고를 억제하는 지금 방식을 유지한다.
- "(수정됨)" 표시는 시각 뒤에 그대로 둔다.

### 비밀번호 불일치 안내

- 수정 폼에서 403 `INVALID_PASSWORD`를 받으면 토스트와 함께 비밀번호 칸 아래에 서버 message("비밀번호가 일치하지 않습니다")를 표시한다. 비밀번호를 다시 입력하기 시작하면 지운다(기존 필드 오류 규칙과 같다).
- 삭제 창에서도 403이면 토스트와 함께 비밀번호 칸 아래에 같은 문구를 표시하고, 창을 열어 둔다.
- 서버의 비밀번호 검증 동작(403, 내용 불변)은 바꾸지 않는다.

### 요청 횟수 제한

- 작성과 비밀번호 확인(수정·삭제 합산) 모두 IP당 1분 **30회**로 올린다. 윈도 방식, IP 판정, Reaction·조회 무제한은 그대로다.
- 기본 스펙의 "IP당 1분에 5회" 결정을 이 스펙이 대체한다.

### 앱 이름

- `package.json`의 `name`을 `guestbook-202204092`로 바꾼다. 화면의 서비스명 "Mini Kudos"는 그대로 둔다(방명록 서비스의 이름이다).
- README 첫머리에 개발자 정보와 "배포 URL" 자리를 두고, 저장소 이름 규칙을 적는다.

## 테스트 결정 (Testing Decisions)

- **좋은 테스트의 기준**: 기존과 같다. 겉에서 관찰 가능한 동작(HTTP 상태 코드, 응답 본문)만 검증한다.
- **주 경계 — Route Handler (기존)**:
  - 작성: 이름 누락·빈 문자열·공백만이면 400과 `fieldErrors.author` "이름을 입력해 주세요". 이름이 있으면 201. "빈 작성자는 '익명'"을 기대하던 기존 테스트는 새 규칙에 맞게 바꾼다.
  - 요청 횟수 제한: 같은 IP의 31번째 작성·비밀번호 확인이 429이고, 30번째까지는 통과한다. 다른 IP는 영향이 없다. 분 경계 대기 로직은 유지한다.
  - 비밀번호 검증(회귀): 틀린 비밀번호로 수정·삭제를 여러 번(예: 6번) 시도해도 매번 403 `INVALID_PASSWORD`이고, 그 뒤 올바른 비밀번호로 수정·삭제가 성공한다. 과거 한도(5회)였다면 실패했을 시나리오다.
- **보조 경계 — 순수 함수 (기존 온도·열 분배 테스트와 같은 방식)**: 작성 시각 포맷. 기대값은 직접 계산한 리터럴로 둔다. 예: `2026-09-30T05:05:00Z` → "9월 30일 14:05", 자정을 넘는 UTC 시각의 한국 날짜, 다른 해 → 연도 포함.
- **수동 확인**: 헤더의 개발자 정보(데스크톱·모바일 폭, 모든 페이지), 이름 칸 라벨과 필수 오류, 비밀번호 불일치 시 입력칸 아래 안내(수정·삭제), 카드의 작성 시각 표기.
